## 3. 新增需求：上传图书（txt/epub 电子书一键入库）`[新增]`

### 3.1 背景与诉求

现有站点只能由「作家账号」在作者后台**逐章**手写发布内容；无法把现成的 txt/epub 电子书整本导入并让前台读者直接阅读、搜索。

### 3.2 功能定义

用户在**前台**（免登录）提交一本 txt 或 epub 电子书，系统自动：

1. 解析文件内容并识别章节；
2. 写入 `book_info`（书目）、`book_chapter`（章节）、`book_content`（正文）三表；
3. 更新书目的字数 / 最新章节 / 更新时间；
4. 上传完成后，该书出现在前台首页 / 搜索结果中，可正常阅读。

### 3.3 用户可见流程

```
选择文件(txt/epub)
→ 填写：书名、作者名、分类、作品方向（男频/女频）、简介
→ 点击「上传」
→ 页面显示「解析中…」
→ 成功：提示上传成功，并提供「立即阅读」跳转
→ 失败：页面显示具体错误（文件过大/格式不支持/解析失败/无有效章节）
```

### 3.4 验收标准（用户从前端验证）

- 在「上传图书」页面选择一本 **.txt** 文件并填写信息，点击上传后页面显示上传成功，且该书出现在首页/搜索结果中，点击可正常分章阅读。
- 选择一本 **.epub** 文件重复上述操作，同样成功且可完整阅读。
- 上传一个**超过大小上限**的文件，或一个**非 txt/epub 格式**的文件（如 .pdf），页面给出明确错误提示，不产生脏数据。
- 上传一个**不含有效章节**的乱码/空文件，页面提示解析失败，不写入任何记录。

### 3.5 权限边界（已与用户确认）

- **上传入口放在前台，免登录开放**：任何访问站点的人无需账号即可上传图书。（用户已明确选择此方案，适用本地/内部部署场景。）

### 3.6 归属与作者（本次设计决策，待用户确认）

- 上传的图书**无作家账号**（免登录，无 UserHolder.userId）。
- 设计默认：`author_id = 0`（匿名系统归属），`author_name` 使用用户在表单填写的**作者名**，为空则显示「匿名用户」。
- 优先级：若有更好方案（如自动以文件内的作者信息填充），实现时遵循本 PRD，不擅自引入作家账号绑定。

### 3.7 格式与解析规则

| 格式 | 解析方案 |
|------|----------|
| `.txt` | 编码自动识别（UTF-8 / GBK / UTF-8 BOM）；按章节标题正则（如 `第[XX]章`、`第一章`、`Chapter 1` 等）切分章节；无章节标题时整篇作为单章 |
| `.epub` | ZIP 解压（JDK 内置 `java.util.zip` + 引入 `jsoup`），按 spine 顺序提取正文文本，再按章节规则切分 |
| 其他（`.pdf`/`.mobi`/`.azw3`） | 拒绝，返回「不支持的文件格式」 |

**文字规范**：
- 章节内容入库后 `wordCount` 按 `content.length()` 统计（与现有 `saveBookChapter` 一致）。
- 切片章节**不经过** `@Length(min=50)` 校验（该校验仅用于作者逐章发布），短章节不因长度被拒。
- 解析出的正文需做基本清洗：去除多余空行、章节标题行标记、html 标签（epub）。

### 3.8 配置变更

| 配置项 | 现状 | 变更 |
|--------|------|------|
| `spring.servlet.multipart.max-file-size` | `5MB` | 调至 `100MB`（并补 `max-request-size`） |
| `spring.servlet.multipart.max-request-size` | 未设置 | 补 `100MB` |
| `novel.file.upload.path` | `/Users/xiongxiaoyang/upload`（macOS 路径，Windows 无法写） | 改为 Windows 可用目录（如 `D:/novel-upload`） |

> 提示：`file.upload.path` 为全局上传目录，图片上传与电子书共用；本次一并修正为 Windows 路径。

### 3.9 非目标（本项目本次不做）

- 不支持 `.mobi` / `.azw3` / `.pdf` 解析。
- 不做「从互联网抓取书源」——这是另一需求方向（多书源阅读站），**不在本项目范围**。
- 不针对上传的图书提供作者账号绑定、收益、审核流。
- 不启用 ShardingSphere 分表（保持现状关闭）。

## 3A. 新增需求：我的上传（管理员管理上传图书）`[新增 2026-10-20]`

> 增量需求，来源：用户在「上传图书」功能交付后的修整诉求。本节只增量定义本次改动，不推翻第 3 节已交付的上传功能。

### 3A.1 背景与诉求

上传图书功能已上线，但上传后的书在站内**没有任何管理入口**：无法查看自己上传过哪些书，也无法把书从「连载中」改为「已完结」。本次增加一个仅管理员可用的「我的上传」页，用来查看上传书目并切换连载状态。

### 3A.2 功能定义

1. **管理员账号**：固定账号 `admin` / 密码 `admin`。系统启动时若 `user_info` 中不存在该账号则自动创建，沿用现有前台登录接口 `/api/front/user/login`（MD5 密码）。
2. **归属记录**：`book_info` 新增 `uploader_id` 列，上传成功时写入当前请求者身份；匿名上传写 `0`。
3. **前台导航**：新增「我的上传」入口，**仅管理员登录后显示**；非管理员和非登录用户不可见。
4. **我的上传页**：分页列表（按上传时间倒序）+ 状态筛选（全部 / 连载中 / 已完结）+ 单本切换状态（连载中 ↔ 已完结）。

### 3A.3 用户可见流程

```
管理员 admin 登录
→ 顶部导航出现「我的上传」
→ 进入页面：看到归属于 admin 的上传书分页列表
→ 可按「连载中 / 已完结」筛选
→ 点击某本书的「设为已完结 / 设为连载中」
→ 列表状态即时刷新；前台该书详情页状态同步变化
```

### 3A.4 验收标准（用户从前端验证）

- 未登录访客和普通用户登录后，导航栏**看不到**「我的上传」。
- 用 `admin` / `admin` 登录后，导航栏出现「我的上传」，点击进入可看到上传书目列表（含历史书「仙逆」）。
- 列表按上传时间倒序分页展示，每页 10 条；状态筛选「连载中 / 已完结」能正确过滤。
- 对一本连载中的书点击「设为已完结」，列表状态即时变为已完结；刷新页面、重新登录后仍为已完结；前台该书详情页显示为已完结。
- 再次点击可切回连载中。
- 非管理员（含未登录）直接访问管理接口返回未授权，不能修改任何书状态。

### 3A.5 权限边界（用户已确认）

- 上传入口**保持免登录**（沿用第 3.5 节），本次不改上传权限。
- 归属规则：**上传时若携带有效登录态则记为当前用户 id；匿名上传记为 `0`**，`0` 的书不进「我的上传」列表。
- 历史数据：库中唯一一本上传书「仙逆」**回填**到 admin 名下。
- 「我的上传」仅展示 `uploader_id = 当前登录用户 id` 的书；管理员看到的就是 admin 名下的上传书。

### 3A.6 管理接口权限模型

- 管理接口置于 `/api/front/upload`，**受现有 `AuthInterceptor` 的前台登录校验保护**（需新增拦截前缀），并在 Service/Controller 层校验当前用户是否为管理员。
- 管理员判定口径：`user_info.username = 'admin'`（不新增角色表，避免过度设计）。
- 错误码：未登录 → `A0230`；已登录非管理员 → `A0301`（复用现有）。

### 3A.7 非目标（本次不做）

- 不做管理员角色体系 / 多管理员 / 权限矩阵。
- 不做上传书的编辑、删除、封面更换。
- 不做审核流、上下架。
- 不做作者后台菜单改造。

## 7. 新增需求：全局主题切换（浅色 / 深色）`[新增 2026-10-29]`

> 增量需求，来源：用户在项目交付后的修整诉求「改变整个界面的颜色」。本节只增量定义本次改动，不推翻既有功能与视觉基线。

### 7.1 背景与诉求

站内目前只有一套浅色视觉，长时间阅读正文时眼睛易疲劳。用户希望提供**浅色 / 深色双主题**，可一键切换「整个界面」的颜色。

技术现状（已实测）：前端为 Vue 3 + Element Plus 2.2.0；`element-plus/theme-chalk/dark/css-vars.css` 已在 `node_modules` 内可用，深色能力现成。但**颜色硬编码约 1091 处**（6 个全局 CSS 约 274 处，22 个 views + 11 个组件约 817 处），散落在各 `.vue` 的 `<style>` 内，仅加 `.dark` class 不会自动生效，必须先抽成 CSS 变量再定义主题取值。

### 7.2 功能定义

1. **双主题**：`light`（现状浅色，默认）与 `dark`（深色）。切换后整站配色随之改变，不做「只换主色不动底色」的配色方案模式。
2. **切换入口**：顶部导航栏右上角图标（在 `Top.vue` 的 `bookShelf` 区域内，与「登录 / 注册 / 退出」并列），全站任意页面可用。
3. **偏好持久化**：用户选择记入 `localStorage`，刷新页面、关闭浏览器后重开仍保持上次选择。
4. **首次访问**：无历史偏好时默认浅色，**不**跟随系统 `prefers-color-scheme`（保持与现状一致，避免老用户看到意外变化）。
5. **Element Plus 适配**：引入官方 `dark/css-vars.css`，切换时在 `<html>` 上增删 `dark` class，使 `el-*` 组件（表格、对话框、表单、分页、上传等）跟随主题。
6. **正文阅读页**：`BookContent.vue` 作为长时间阅读场景重点适配，深色下正文底色、正文文字、工具栏均需可读，不得出现深底深字。

### 7.3 用户可见流程

```
任意页面 → 顶部导航栏右上角出现主题切换图标
→ 点击图标：整站由浅色切为深色（图标同步变为对应的反向图标）
→ 浏览首页 / 全部作品 / 排行榜 / 书籍详情 / 正文阅读 / 登录注册 / 用户中心 / 上传 / 我的上传 / 书籍管理
   → 页面底色、文字、边框、表头、按钮、弹窗均为深色系，文字清晰可读
→ 刷新页面：仍为深色
→ 再次点击图标：切回浅色，刷新后仍为浅色
```

### 7.4 验收标准（用户从前端验证）

- 任意页面顶部导航栏右上角都能看到主题切换图标（未登录、已登录、管理员三种状态下均可见）。
- 点击图标后，**当前页面**底色由浅变深、文字由深变浅，无需刷新即可生效。
- 切换到深色后，依次访问以下页面，均无「深底深字 / 浅底浅字」不可读区域：首页、全部作品、排行榜、书籍详情、正文阅读、登录、注册、用户设置、上传图书、我的上传、书籍管理。
- 深色下表格（书籍管理 / 我的上传）、对话框、表单、分页、上传控件等 Element Plus 组件同样为深色系。
- 深色下正文阅读页顶部工具栏、正文区域、章节导航均为深色系且文字可读。
- 刷新页面后保持上次选择的主题；关闭浏览器重新打开后仍保持。
- 切换主题不影响任何业务功能：登录状态、列表数据、上传、分页、搜索均正常。
- 首次访问（清空 `localStorage`）默认浅色，与改动前的视觉一致。

### 7.5 约束与边界

- **不改业务逻辑**：不触碰任何接口、数据结构、路由语义、登录鉴权。
- **不引入新依赖**：使用 Element Plus 自带 `dark/css-vars.css`，不新增 UI 库或主题框架。
- **不改后端**：纯前端改动，后端零变更。
- **视觉基线不变**：浅色主题的观感须与改动前一致（仅把硬编码颜色抽为变量，取值不变）。
- 不提供「跟随系统」选项，不提供多套配色方案（暖橙 / 蓝调等），不在用户设置页重复放置入口。

### 7.6 非目标（本次不做）

- 不做主题切换的过渡动画 / 渐变切换效果。
- 不做按页面差异化主题（如「仅阅读页深色」）。
- 不做后端持久化主题偏好（不新增用户字段与接口）。
- 不做高对比度 / 护眼绿等无障碍主题。

### 7.7 外部依赖

本次**不引入任何新外部服务**，无 Key 需索取；Tester 沿用本机 MySQL / Redis（8888 / 1024 端口）完成真实联调即可。
