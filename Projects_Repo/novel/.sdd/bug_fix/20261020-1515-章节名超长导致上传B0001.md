# Bug 修复报告：章节名超长导致上传返回「系统执行出错」

## 用户原话

> 这个网站我在上传一个图书的时候上传错误，显示系统执行出错

## 经验回查

- 是否已有相关经验：否（同模块已有 B0001 经验，但那是 `book_info.pic_url` NOT NULL 缺默认值，不是本问题）
- 相关经验：
  - `Bugfix: book_info.pic_url NOT NULL 无默认值导致上传 B0001`
- 为什么仍然犯错：本次为同一接口的新变体，触发点是解析出的 `chapter_name` 超过数据库字段长度，历史经验未覆盖字段长度约束。

## 问题分析

- 现象：上传图书时接口返回 `B0001 系统执行出错`。
- 影响范围：`POST /api/front/resource/book/upload`；章节标题超过 100 字符的 txt/epub 上传失败。
- 直接原因：后端插入 `book_chapter.chapter_name` 时抛出 `MysqlDataTruncation: Data too long for column 'chapter_name' at row 1`，被全局异常处理兜成 `B0001`。
- 根本原因：上传链路没有在入库前按 `book_chapter.chapter_name varchar(100)`、`book_info.last_chapter_name varchar(50)` 等数据库字段长度做截断或校验，解析器可能产出任意长度的章节标题。

## 修复方案

- 修改文件：`Projects_Repo/novel/src/main/java/io/github/xxyopen/novel/service/impl/BookUploadServiceImpl.java`
- 修改说明：
  - 在 `doUploadBook` 入库前对 `category_name`、`book_name`、`author_name`、`book_desc`、`chapter_name`、`last_chapter_name` 按数据库字段最大长度安全截断。
  - 新增 `truncate(String, int)` 工具方法，按 Unicode code point 计数，避免切断 emoji 等代理对。

## 验证方式

- 前端验证：重新上传标题超过 100 字符的 txt 文件，页面应提示上传成功。
- 终端验证：
  - 上传长标题 txt 后接口返回 `code=00000`。
  - 查询数据库 `CHAR_LENGTH(chapter_name)=100`、`CHAR_LENGTH(last_chapter_name)=50`。
  - 清理测试数据后 `book_info/book_chapter/book_content` 恢复基线 `107/11137/11137`。
