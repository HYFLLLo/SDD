  进程异常退出后按 PID 存活检测自动接管，不会永久锁死。
- 日志写入 `workspace/logs/app.log`（2MB × 3 轮转）。静态资源与高频轮询降级为

- `/api/version` 返回版本、构建时间、提交号、Python 与运行形态；帮助页展示版本行。
- 路径用例覆盖中文、空格、旧版数据集兼容、跨盘穿越拒绝与超过 260 字符的路径。
- CI 以仓库内 `bytecode_match.json` 为基线，`missing > 0` 或 `diff` 增加即失败。
- 新手引导步骤切换不再等待目标元素：文案同步渲染，目标用 50/90ms 短轮询补齐，

- onefile 每次启动都要把全部资源解包到 `%TEMP%` 再逐个扫描；原包 98MB / 2708 个文件

  numpy/boto3/botocore/cryptography、tzdata 与 AVIF 解码器，保留 PIL 的
  jpg/png/bmp/webp 能力；稳态启动 5.5s，冷启约 8.3s。`multimodaltest_onedir.spec`

## 7. 反编译装配：函数默认值丢失（2026-11-10 修复）

**根因**：Python 3.8 把函数默认值存放在**父级** code object 的 `MAKE_FUNCTION` 指令前
（`BUILD_TUPLE` + `LOAD_CONST '<qualname>'`），不在函数自己的 code object 里。
`tools/recover/assemble.py` 的「逐函数反编译 + 拼回」只反编译函数自身的 code object，
因此**所有被重建函数的默认参数都被静默丢弃**，且语法合法、编译通过、单测不覆盖。

**症状**：配置页站点卡片「测试」失败（`self._resolve(site=site)` 缺 `model` 默认值抛
`TypeError`），而「测试全部站点」走 `list(self.sites)` 不碰 `_resolve`，所以成功。
同一根因还影响 `has_keys()`、`recommended_concurrency()`、`chat_*()`、`_clip()`、
`optimize()`、`derive_verdict()`、`_meta()` 等 9 处调用点。

**修复**：新增 `tools/recover/apply_defaults.py`。它用模块/类 scaffold（由父级 body 反编译，
仍保留默认值）读出每个函数尾部参数的默认值**源码文本**，按 AST 位置只改写签名行，
不触碰函数体。装配后运行一次即可回填。

    $env:PYTHONPATH='E:\OpenCode Work\decomp'; $env:DECOMP_DIR='E:\OpenCode Work\decomp'
    C:\Users\huyufeng7\litellm\venv\Scripts\python.exe tools\recover\assemble.py
    C:\Users\huyufeng7\litellm\venv\Scripts\python.exe tools\recover\apply_defaults.py

**验证**：

- `git diff --stat app` 仅 13 个文件 44 行，全部是签名行；
- 同模块「`self.x()` 缺必填参数」扫描 **0 处**（修复前 9 处）；
- `test_connection(site='S')` 由 `TypeError` 变为真实网络结果；
- `pytest -q` **214 passed**（原 200 + 新增 14 条防复发用例）；
- 字节码对拍 **exact 592 / near 10 / diff 21 / missing 0**，基线未劣化。

**避免重蹈**：`tests/test_recovered_defaults.py` 锁定关键签名，并固化了
「同模块调用不得漏传必填参数」的静态扫描；以后重跑装配若不执行
`apply_defaults.py` 会直接失败。
