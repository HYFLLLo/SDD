# 多模态测试平台 — 产品需求说明（反向整理）

> 来源：由已有 exe 的源码恢复结果（`app/`、`web/`）与运行时接口反向整理，**未经原厂确认**。
> 用途：作为 SDD 接管后的现状基线，后续需求变更以本文件 + `docs/Plan.md` 为准。
> 整理日期：2026-11-05

## 1. 产品定位

面向"多模态大模型能力评测"的本地单机工作台。使用者把自己的图片集、提示词、人工真值喂进去，
让模型批量跑图，再用人工审核 + 裁判模型 + 自动优化闭环，回答三个问题：

1. 当前提示词在给定图片集上的准确率如何；
2. 错在哪里（误报 / 漏报 / 部分正确 / 无法判断），失败集中在哪个提示词模块；
3. 提示词怎么改才能更好，改完是否真的提升（可回归对比）。

**非目标**：不做多租户、不做在线服务、不做模型训练；默认只监听 `127.0.0.1`，数据全部落本地文件系统。

## 2. 用户与运行形态

| 项 | 现状 |
|----|------|
| 使用者 | 单人 / 小团队评测同学 |
| 部署 | `多模态测试平台.exe` 双击启动，自动开浏览器；默认端口 8735，被占用则顺延 |
| 数据根 | `workspace/`（可用 `MMTEST_WORKSPACE` 覆盖），纯文件，无数据库 |
| 模型接入 | OpenAI 兼容协议；多站点、每站点多 Key、多模型 |
| 鉴权 | 无（依赖本机绑定 + Host 白名单） |

## 3. 领域模型

```
项目 Project ──< 图片集 Dataset ──< 图片 Image（含 split 分组）
                      │
                      ├──< 真值任务 TruthTask ──< 单图标签
                      │
提示词 Prompt ──< 版本 Version（V1..Vn，五段式）
                      │
                      └──< 运行 Run（图片 × 版本 × repeat）
                                ├── 结果 Result（解析后的状态/目标/分类）
                                ├── 人工审核 Review（verdict + expected_objects）
                                ├── 裁判 Judgment（fault_location 八模块 + 建议）
                                └── 优化记录 Optimization（候选新版本）
运行 Run × 真值任务 TruthTask ──> 评估 Eval（accuracy / P-R-F1 / 混淆矩阵）
```

### 3.1 提示词五段式

`role / task / definition / workflow / output_format`。其中 `output_format` 在自动优化链路中被哈希锁定，
优化器只能改前四段，越权修改会被拒绝——这是防止"改协议骗指标"的关键约束。

### 3.2 运行与复现

- 一个运行 = 数据集快照 + 提示词版本快照 + 模型参数 + 结果目录；运行目录内保存原图快照，
  后续删改图片集不影响历史结果查看。
- `repeat` 支持同一图多次调用，用于稳定性统计（同类结果占比 / 标签一致率）。
- 运行、裁判、优化均为后台线程任务；进程重启后对账为 `interrupted` / `已暂停`，支持续跑。

### 3.3 审核与真值

- 人工审核 verdict：`正确 / 误报 / 漏报 / 部分正确 / 无法判断`。
- 审核结果可沉淀为真值任务；重复运行可依据图片 SHA-256 复用人工基线，避免重复劳动。
- 真值优先"人工优先 + 自动补齐"。

## 5. 非功能需求（现状基线）

- **性能**：列表接口使用目录指纹缓存，避免轮询全量扫描；首页采用 stale-while-revalidate。
- **并发**：运行并发 1–20，单 Key 并发 1–8，可按 Key 数量自动限制有效并发；429 有冷却。
- **可靠性**：后台任务心跳与重启对账；写盘采用临时文件 + 原子替换（见 `app/schema.py`、`app/runner.py`）。
- **安全**：仅绑定 `127.0.0.1`；Host 白名单（`127.0.0.1/localhost/::1`，可用 `MMTEST_ALLOWED_HOSTS` 扩展）；
  CSP、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；API Key 在配置接口中掩码；
  `safe_path()` 阻止目录穿越。
- **可访问性**：全部表单控件具备可访问名称；模态框有焦点陷阱与 Esc 关闭；提供跳转主内容链接与
  `:focus-visible`；长任务显示百分比进度。
- **兼容**：Windows 单文件 exe（Python 3.8 构建）；支持含中文与空格的安装路径。

## 6. 外部依赖与配置

| 依赖 | 用途 | 配置位置 |
|------|------|----------|
| OpenAI 兼容 API（MaaS 等） | 图片理解 / 裁判 / 优化 | `workspace/config.json` 的 `api.sites[]`（name、base_url、api_keys、models） |
| 运行参数 | 默认模型、并发、超时、重试、max_tokens、温度 | `defaults` 段 |
| 环境变量 | `MMTEST_WORKSPACE`、`MMTEST_PORT`、`MMTEST_NO_BROWSER`、`MMTEST_ALLOWED_HOSTS` | 进程环境 |

真实 Key 只存在于本地 `workspace/config.json`，已被 `.gitignore` 排除，不得写入文档或仓库。

## 7. 已知限制（P2 及以后）

- 前端仍是单文件 SPA（约 4,000 行，105 处 `innerHTML`），无构建链与模块化。
- 移动端仅基础适配，无折叠菜单；无暗色模式。
- 72+ 路由无鉴权（本地单机场景风险可控，但不为零）。
- 裁判/优化结果依赖模型质量，平台只保证流程与协议约束，不保证结论正确性。
